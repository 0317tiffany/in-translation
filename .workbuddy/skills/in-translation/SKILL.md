# In Translation — 思考过程双语转换

## 概述

把 AI agent 的英文思考过程转换为「中文为主 + 英文折叠对照」的双语形式，让中文用户真正读懂 agent 是怎么想的。翻译遵循信达雅标准，优先级固定为 **信 > 达 > 雅**。

## 工作流

### Step 1：确定输入来源

按以下顺序识别，取第一个命中的：

| 来源 | 识别方式 | 处理 |
|---|---|---|
| 当前会话思考 | 用户说"翻译你刚才的思考 / 上一轮的思考" | 从上文提取 agent 最近产生的英文 thinking |
| 粘贴文本 | 用户消息中包含成段的英文思考内容 | 直接使用该文本 |
| 文件 | 用户给出路径（.md / .txt 等） | 读取文件中的思考记录 |

三者都无法确定时，向用户询问，不要猜测。

### Step 2：预处理

1. **标记不译内容**，翻译时原样保留：
   - 代码块（围栏内）与行内代码
   - shell 命令、文件路径、URL
   - 变量名、函数名、类名、参数名
   - JSON / YAML / XML 等结构化数据片段
2. **按语义分段**：以一个完整推理单元为一段（一个假设、一次推演、一个决定）。不按句子硬切，保证推理链完整。

### Step 3：翻译

翻译前加载 `references/translation-guide.md` 并遵循其细则。核心规则：

- **信（最优先）**：忠实原意，不增不减不歪曲；代码、命令、术语原样保留
- **达**：符合中文技术表达习惯，可调整语序，消除翻译腔
- **雅**：仅在信达之内润色，不为文采牺牲准确性
- **术语保留英文**：API、token、hook、prompt、agent 等开发者通用术语不翻译（完整清单见 translation-guide.md）
- **保留思考质感**：wait→"等等"、hmm→"嗯"；自我修正如实翻译（"不对，应该是……"）；First / Second / Finally 等推理链标记保留（"首先 / 其次 / 最后"）

### Step 4：双语输出

采用「中文在上 + 英文折叠」格式。短思考（≤3 段）用单个折叠块；长思考按逻辑章节分组，每组一个折叠块。

模板：

```markdown
## 🧠 思考过程（中文）

[中文译文]

<details>
<summary>📄 查看英文原文</summary>

[English original]

</details>
```

注意事项：

- `<details>` 标签前后必须留空行，否则 Markdown 不渲染
- 折叠块内的英文保持原文的段落结构与代码块
- 不译内容（代码、命令等）在中文译文中原样出现，缩进与原文一致

### Step 5：可选保存文件

用户要求保存时，将双语结果写入 .md 文件（默认文件名 `thinking-bilingual-<YYYYMMDD-HHMM>.md`，或用户指定路径），文件头部注明来源与翻译时间。

## 质量自检

输出前快速核对：

- [ ] 无漏译：原文每个语义段都有对应中文
- [ ] 不译内容原样：代码、命令、路径未被翻译
- [ ] 术语保留：API / token / hook 等保持英文
- [ ] 思考质感保留：修正、犹豫、推理链未被抹平
- [ ] 折叠块可渲染：`<details>` 前后有空行
